## One-Line Install (macOS / Linux)

```bash
curl -fsSL https://raw.githubusercontent.com/floruntime/flo/dev/scripts/install.sh | sh
```

This installs the newest release's `flo` binary to `/usr/local/bin` on Linux and
`/opt/homebrew/bin` on macOS, after checking its SHA-256. Pass `--version <tag>` to pin a
release, or `--dir <path>` to install elsewhere.

## Release Tarballs

Download `flo-<arch>-<os>.tar.gz` for your platform from
[Releases](https://github.com/floruntime/flo/releases). Each has a `.sha256` beside it.

The macOS binaries need macOS 15 or later.

## Linux Packages (.deb / .rpm)

Each release has a `.deb` and an `.rpm` for x86_64 and aarch64 on
[Releases](https://github.com/floruntime/flo/releases), each with a `.sha256` beside it.
They install `flo` as a systemd service.

```bash
# Debian, Ubuntu
sha256sum -c flo_<version>_amd64.deb.sha256
sudo apt install ./flo_<version>_amd64.deb

# Fedora, RHEL, Rocky
sha256sum -c flo-<version>-1.x86_64.rpm.sha256
sudo dnf install ./flo-<version>-1.x86_64.rpm
```

A pre-release like `0.1.0-dev.12` is packaged as `0.1.0~dev.12`. On aarch64 the files are
`flo_<version>_arm64.deb` and `flo-<version>-1.aarch64.rpm`.

The package installs the service but doesn't enable or start it. Check the config first,
then:

```bash
sudo systemctl enable --now flo
```

| | |
|---|---|
| Binary | `/usr/bin/flo` |
| Config | `/etc/flo/flo.toml` |
| Data | `/var/lib/flo`, owned by the `flo` user |
| Service | `flo.service`; logs with `journalctl -u flo` |

The packaged config binds the client port (9000), the dashboard and metrics to
`127.0.0.1`, since clients aren't authenticated yet. To serve other hosts, set `bind` in
`[server]` to a private interface's address and keep the port behind a firewall.

An upgrade (installing a newer package) keeps your edits to `flo.toml` and restarts the
service if it is running. Removing the package stops and disables the service but keeps
the data, the config and the `flo` user; on Debian, `apt purge flo` also removes
`/etc/flo`. The data in `/var/lib/flo` is never removed by the package. To delete it:

```bash
sudo rm -rf /var/lib/flo
```

## Docker

```bash
docker run -p 9000:9000 -p 9001:9001 -p 9002:9002 ghcr.io/floruntime/flo:latest
```

`latest` is the newest release. To pin one, use its tag without the leading `v`,
e.g. `ghcr.io/floruntime/flo:0.1.0-dev.12`; [the registry](https://github.com/floruntime/flo/pkgs/container/flo) lists them.

See the [Docker deployment guide](/deployment/docker/) for production usage with volumes and compose.

## Building from Source

Requires [Zig 0.17.x](https://ziglang.org/download/); the build refuses any other version.

```bash
git clone https://github.com/floruntime/flo.git
cd flo
zig build -Drelease=true
```

The binary is at `zig-out/bin/flo`.

## Verify Installation

```bash
flo --version
```

## Default Ports

| Port | Purpose |
|------|---------|
| `9000` | Client API (binary protocol) |
| `9001` | Prometheus metrics (auto: port + 1) |
| `9002` | Dashboard web UI (auto: port + 2) |
