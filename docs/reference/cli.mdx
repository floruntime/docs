## Global Options

| Flag | Description |
|------|-------------|
| `-e, --endpoint <host:port>` | Server endpoint; else `FLO_ENDPOINT`, else `127.0.0.1:9000` |
| `-p, --port <port>` | Server port on `127.0.0.1`, when `--endpoint` isn't given; else `FLO_PORT` |
| `-n, --namespace <name>` | Namespace for operations; else `FLO_NAMESPACE`, else `default`. Given, it always wins, `-n default` included |
| `-o, --output <fmt>` | Output format: `table`, `json`, `raw` |
| `-v, --verbose` | Verbose output |
| `-V, --version` | The release, such as `flo 0.2.0`, or `flo dev` for a development build. `flo version --verbose` adds the protocol version, op table hash and build. A server serves only clients built from its table; a mismatch exits 5 naming both tables. |

`-e`, `-p`, `-n`, `-o` and `-v` mean the same thing on every command; no command reuses those letters for a flag of its own.

## Errors and exit codes

A refused command prints `Error: <message> [<status>]`, or `[<status>/<reason>]` when the server names a [reason](/reference/wire-protocol#refusals), e.g. `[bad_request/out_of_range]`, and exits:

| Code | Meaning |
|------|---------|
| `0` | ok |
| `1` | not found or absent |
| `2` | usage error |
| `3` | refused (`bad_request`, `conflict`, `unauthorized`, `internal_error`) |
| `4` | retryable (`overloaded`, `rate_limited`, `unavailable`) |
| `5` | transport failure, timeout, version mismatch, a cut-off answer, or the CLI out of memory |

## Namespaces

:::note
**Namespaces aren't a security boundary.** A namespace separates names, not access. Clients aren't authenticated yet, so
anything that can reach the client port can read and write every namespace.
Keep the port on a private interface.
:::

A namespace is created by `flo ns create <name>`, or by the first write that
brings data into it (a delete, a dequeue or an ack never creates one). Either way the name is 1–63 bytes of lowercase letters, digits,
`_` and `-`, starts with a letter or digit, and does not end in `-`; names
starting with `_` are the system's. A request naming any other namespace is
refused with the reason. Each shard holds at most 1024 namespaces, and
`default` always has room.

```bash
flo ns create <name>
flo ns ls
flo ns info <name>
```

Deleting a namespace isn't supported yet: `flo ns delete` is refused, with or
without `--force`, and removes nothing. A namespace's data lives on every
shard, and its name can't yet be retired so that a later create doesn't
inherit it.

## Server

### `flo server start`

Start a Flo server.

```bash
flo server start [options]
```

| Flag | Description | Default |
|------|-------------|---------|
| `-c, --config <path>` | Config file path | `flo.toml` |
| `-p, --port <port>` | Client protocol port; `0` binds a free one, printed in the ready line and by `server status` | `9000` |
| `--bind <addr>` | Address to listen on | `0.0.0.0` |
| `-d, --data-dir <path>` | Data directory | `~/.flo/data` |
| `--durability <mode>` | `sync` or `async_flush` | — |
| `-s, --shards <n>` | Number of shard threads, at most 256; a cluster member runs 1 (the default resolves to it) | CPU count, less one on 4 or more cores |
| `--partitions <n>` | Virtual partitions, at most 16384 | `max(4096, shards × 32)` |
| `-l, --log-level <level>` | `debug`, `info`, `warn` or `error` | — |
| `--log-format <format>` | `text` or `json` | — |
| `--cluster` | Start as the first member of a cluster; leads alone until others join | — |
| `-j, --join <host:port,...>` | Join members that exist, by their peer port (`listen_port + 500`) | — |
| `--node-id <id>` | Unique node identifier | derived from `hostname:port` |
| `--raft-port <port>` | Peer port, with `--cluster` or `--join` | `listen_port + 500` |
| `--metrics-port <port>` | Metrics HTTP port | `listen_port + 1` |
| `--dashboard-port <port>` | Dashboard HTTP port | `listen_port + 2` |
| `--no-metrics` | Don't start the metrics server | — |
| `--no-dashboard` | Don't start the dashboard | — |

### `flo server secret`

Print a new secret for the peer port, from 32 random bytes. Give every member
the same one: in `[cluster] secret`, in a file named by `[cluster] secret_file`
(mode 600), or in `FLO_CLUSTER_SECRET`. A cluster starts only with a secret in
this form.

```bash
flo server secret > /etc/flo/cluster.secret
chmod 600 /etc/flo/cluster.secret
chown flo:flo /etc/flo/cluster.secret   # the user the server runs as
```

The server refuses a `secret_file` that its group or others can read or write.

### `flo server inspect`

Show a stopped node's cluster log: its hard state, last index and term, what
is committed, the latest member list, and whether its lost-log guard is on.
Writes nothing. Refuses while a
server holds the data directory, and refuses a directory that does not exist.

```bash
flo server inspect --data-dir /var/lib/flo
```

| Flag | Description | Default |
|------|-------------|---------|
| `-c, --config <path>` | Config file naming the data directory | `flo.toml` |
| `-d, --data-dir <path>` | Data directory | from the config |

### `flo server force-members`

Make a stopped node the cluster's only voter, for when a majority has lost its
data. Without `--yes` it prints what it would change and stops. With `--yes`
it writes a member list naming only this node and retires its cluster secret;
restart it with a new one. See [Clustering](/deployment/clustering#when-a-majority-lost-its-data).

```bash
flo server force-members --data-dir /var/lib/flo --yes
```

| Flag | Description | Default |
|------|-------------|---------|
| `-c, --config <path>` | Config file naming the data directory and the secret | `flo.toml` |
| `-d, --data-dir <path>` | Data directory | from the config |
| `--yes` | Make the change | — |

### `flo server status`

Show whether the server process is running and the port it bound, from its PID file.

```bash
flo server status [--config <path>] [--data-dir <path>]
```

It finds the data directory as `server start` does: `--data-dir`, else the config file's `data_dir`, else `~/.flo/data`.

### `flo server stop`

Stop the server whose PID file is in the data directory.

```bash
flo server stop [--config <path>] [--data-dir <path>] [--force]
```

| Flag | Description |
|------|-------------|
| `-c, --config <path>` | Config file naming the data directory |
| `-d, --data-dir <path>` | Data directory holding the PID file (overrides the config) |
| `-f, --force` | Stop at once (SIGKILL) |

### `flo server metrics`

Fetch the server's metrics.

```bash
flo server metrics [--endpoint <host:port>] [--format text|json]
```

`text` prints the Prometheus exposition as served; `json` prints `{"metrics": "<exposition>"}`. `--endpoint` defaults to `localhost:9001`.

## KV

The KV commands are generated from the KV op table: each flag is a field of the op's request, named after it (`ttl_ms` is `--ttl-ms`), and each command sends one request. Their output follows the answer's fields:

- most print one `name: value` line per field (`version: 3`), leaving out a field the answer doesn't carry; an answer with no fields prints `OK`;
- `get`, `incr` and `json get` print the value alone;
- `scan` and `history` print rows;
- `-o json` prints the whole answer as one JSON object, for every command; an integer past 2^53 (a transaction id, a routing hash) is a string, so `jq` and JavaScript don't round it.

A flag whose name ends in `-ms` takes milliseconds, or a number and a unit (`500ms`, `30s`, `5m`, `1h`, `1d`). A value outside a flag's range, or not one of its choices, exits 2 naming the flag. A key that isn't there exits 1 with `not found`.

### `flo kv set`

Set a key's value.

```bash
flo kv set <key> <value> [options]
```

| Flag | Description |
|------|-------------|
| `--ttl-ms <ms>` | Time to live; omitted for none |
| `--condition <when>` | `always` (the default), `if_absent` (only if the key doesn't exist) or `if_present` (only if it does) |
| `--cas-version <version>` | Only if this is the key's version; `0` means the key doesn't exist |
| `-r, --routing-key <key>` | Explicit shard routing key |
| `-t, --txn <id>` | Buffer the write in a transaction |

It prints `version: <n>`, or `OK` inside a transaction, where the write has no version until it commits. A failed condition or version exits 3 with `[conflict/condition_failed]` or `[conflict/cas_mismatch]`.

### `flo kv get`

Read a key's value, and print it alone.

```bash
flo kv get <key> [options]
```

| Flag | Description |
|------|-------------|
| `-w, --wait-ms <ms>` | How long to wait, at most `5m`; `0` (the default) doesn't wait |
| `--wait-for <what>` | `exists` (the default: answers at once if the key exists, else when it's written) or `change` (the key's next version). On timeout, a change wait prints the unchanged value; a key still absent exits 1 |
| `-r, --routing-key <key>` | Explicit shard routing key |
| `-t, --txn <id>` | Read inside a transaction, seeing its buffered writes; it can't wait |

`-o json` prints `{"version":<n>,"value":"<value>"}`.

### `flo kv mget`

Get many keys in one call. Keys may live on different shards; the server gathers them.

```bash
flo kv mget <key1> <key2> ... [options]
```

| Flag | Description |
|------|-------------|
| `-r, --routing-key <key>` | The routing key every key was written with: all are read from its shard |

At most 256 keys per call. Keys written with a routing key are found only with that routing key; mget them together with `-r`, and those written with another, or none, in a separate call. A missing key prints `(nil)`; it isn't an error. When the answers don't fit one response, the CLI asks again from where the server stopped.

### `flo kv delete`

Delete a key. Deleting a key that doesn't exist succeeds.

```bash
flo kv delete <key> [options]
```

| Flag | Description |
|------|-------------|
| `--cas-version <version>` | Only if this is the key's version (race-free lock release) |
| `-r, --routing-key <key>` | Explicit shard routing key |
| `-t, --txn <id>` | Buffer inside a transaction |

It prints `existed: true` or `existed: false`, or `OK` inside a transaction, where whether the key existed isn't known until commit.

### `flo kv scan`

List key names starting with a prefix, a page at a time. Values aren't returned; use `get` or `mget`.

```bash
flo kv scan [prefix] [options]
```

| Flag | Description |
|------|-------------|
| `-l, --limit <n>` | Most names on the page: 1 to 1024, default 1024 |
| `--cursor <hex>` | Where the last page stopped; omit to start |

It prints one name per line, then `cursor: <hex>` when there are more; pass that to `--cursor` for the next page. With `-o raw` the cursor line goes to stderr, so stdout is names alone for a `while read` loop:

```bash
flo kv scan user: --limit 100
flo kv scan user: --limit 100 --cursor 0300
```

### `flo kv history`

Show a key's versions, newest first.

```bash
flo kv history <key> [options]
```

| Flag | Description |
|------|-------------|
| `-l, --limit <n>` | Most versions to show: 1 to 65, default 10 |
| `-r, --routing-key <key>` | Explicit shard routing key: give the one the key was written with |

Each row is the version, the time it was written (`at_ms`, Unix milliseconds) and the value, under a header; `-o raw` leaves the header out.

### `flo kv incr`

Add to an `i64` counter, starting from 0. It prints the new value.

```bash
flo kv incr <key> [--delta <n>]
```

| Flag | Description |
|------|-------------|
| `-d, --delta <n>` | What to add, may be negative (default `1`) |
| `-r, --routing-key <key>` | Explicit shard routing key |
| `-t, --txn <id>` | Buffer inside a transaction; prints `OK`, since the value isn't known until commit |

A key whose value isn't an 8-byte counter is refused with `wrong_type` (exit 3).

### `flo kv expire`

Set an existing key's TTL without rewriting its value, or clear it.

```bash
flo kv expire <key> --ttl-ms 30s   # expires 30s from now
flo kv expire <key> --ttl-ms 0     # clears the TTL
```

| Flag | Description |
|------|-------------|
| `--ttl-ms <ms>` | Required; `0` clears the TTL |
| `--cas-version <version>` | Only if this is the key's version (race-free lease renewal) |
| `-r, --routing-key <key>` | Explicit shard routing key |
| `-t, --txn <id>` | Buffer inside a transaction |

It prints `OK`. A missing key exits 1.

### `flo kv exists`

Existence check, with no value transferred. It prints `exists: true` and `version: <n>`, exiting `0`, or `exists: false` and `version: 0`, exiting `1`. Inside a transaction a key with only a buffered write prints `version: 0`: it has no version until commit.

```bash
flo kv exists <key> [-r <routing-key>] [-t <txn-id>]
```

### `flo kv json get` / `set` / `del`

Read and write inside a JSON document, using a small JSONPath subset (`$`, `.field`, `[index]`). `--path` defaults to `$`, the whole document.

```bash
flo kv json set <key> <document> [--path <path>]
flo kv json get <key> [--path <path>]
flo kv json del <key> [--path <path>]
```

- `json get` prints the JSON at the path.
- `json set` prints `version: <n>`. At `$` it writes the whole document, creating the key; at any other path the key must already hold a JSON object or array.
- `json del` prints `version: <n>`, or `OK` at `$`, which deletes the key.

A path with nothing at it exits 1; a key whose value isn't JSON is refused with `wrong_type` (exit 3). All three take `-r, --routing-key`; none run inside a transaction.

### `flo kv txn begin` / `commit` / `rollback`

Per-shard transactions buffer writes on one pinned partition and commit them atomically as one Raft entry.

```bash
flo kv txn begin <routing-key>        # → txn: <id>, pinned: <hash>
flo kv txn commit <txn-id>            # → commit_index: <index>, ops: <n>
flo kv txn rollback <txn-id>          # drops the buffered writes
```

Add `--txn <id>` to `set`, `get`, `delete`, `incr`, `expire` or `exists` to run it inside the transaction:

```bash
TXN=$(flo kv txn begin user:42 | sed -n 's/^txn: //p')
flo kv set  user:42:name "Jane" -r user:42 --txn "$TXN"
flo kv incr user:42:visits      -r user:42 --txn "$TXN"
flo kv txn commit "$TXN"
```

The transaction id names its shard, so `commit` and `rollback` need nothing else. Ops inside a transaction must give the routing key it was begun with, otherwise they are refused with `wrong_routing_key`. `scan`, `mget`, `history` and the JSON commands don't run inside transactions.

**Server caps**: 256 ops per transaction, 1 MiB total payload, 1024 open transactions per shard (past that, `txn begin` is refused with `too_many_transactions`). Transactions outlive connections: they are owned by their id, not by the TCP connection. One that goes 30 seconds without a request is dropped, and later use is refused with `no_such_transaction`.

## Streams

### `flo stream create`

Create a stream.

```bash
flo stream create <name> [options]
```

| Flag | Description |
|------|-------------|
| `--partitions <n>` | Number of partitions (default 1) |
| `--retention`, `-r <hours>` | Keep records this many hours (0 = no age bound) |
| `--retention-count <n>` | Keep at most this many records (0 = no count bound) |

### `flo stream alter`

Change a stream's retention. A bound left out, or given as 0, keeps its current value.

```bash
flo stream alter <name> [--retention <hours>] [--retention-count <n>]
```

### `flo stream append`

Append a record to a stream.

```bash
flo stream append <stream> <data>
```

### `flo stream read`

Read records from a stream.

```bash
flo stream read <stream> [options]
```

| Flag | Description |
|------|-------------|
| `--start`, `-s <id>` | Read records after this StreamID (exclusive; `0-0` is the beginning, `$` the latest) |
| `--end <id>` | Last StreamID to read (inclusive) |
| `--limit`, `-l <n>` | Maximum records (default 10); a larger append comes back whole |
| `--block`, `-b <ms>` | Wait for new records (at most 300000 ms, 5 minutes; 0 does not wait; a longer wait is refused) |
| `--follow`, `-f` | Keep reading new records, like `tail -f` |
| `--partition`, `-P <n>` | Partition to read |
| `--partition-key`, `-k <key>` | Read the partition this key routes to |

### `flo stream info`

Show stream metadata.

```bash
flo stream info <stream>
```

### `flo stream delete`

Delete a stream and all its data (records, metadata, and name registry). Aliased as `flo stream rm`.

```bash
flo stream delete <name> [--force]
```

| Flag | Description |
|------|-------------|
| `--force`, `-f` | Delete even if the stream is not empty |

Deleting a missing stream is a no-op (idempotent). A non-empty stream is refused unless `--force` is given. Deleting a stream also deletes that stream's consumer groups (a same-named group on another stream is unaffected). To drop only records while keeping the stream, use `flo stream trim`.

### `flo stream group`

Manage consumer groups. A group is scoped to a single stream — every subcommand takes the `<stream>` it operates on, and wildcard/fan-in reads (`events.*`) are not supported.

```bash
flo stream group create <stream> --group <name> [--ack-timeout <ms>] [--max-deliver <n>]
flo stream group read   <stream> --group <name> --consumer <id> [--limit <n>] [--block <ms>]
flo stream group ack    <stream> --group <name> --ids <id,...> [--consumer <id>]
flo stream group nack   <stream> --group <name> --ids <id,...> [--consumer <id>]
flo stream group touch  <stream> --group <name> --consumer <id> --ids <id,...>
flo stream group pending <stream> --group <name> [--consumer <id>]
flo stream group info   <stream> --group <name>
flo stream group join   <stream> <group> <consumer>
flo stream group leave  <stream> --group <name> --consumer <id>
flo stream group delete <stream> --group <name>
```

## Time-Series

### `flo ts write`

Write a point, several fields of one point, or a batch of InfluxDB line protocol.

```bash
flo ts write <measurement> --value <n> [--tags k=v,...] [--timestamp <ms>]
flo ts write <measurement> --fields k=v,... [--tags k=v,...] [--timestamp <ms>]
flo ts write --batch [--file <path>] [--precision ns|us|ms|s]
```

Examples:

```bash
flo ts write cpu --tags host=web-01 --value 82.5
flo ts write cpu --tags host=web-01 --fields user=72.5,system=7.4
echo 'cpu,host=web-01 user=72.5 1708700400000' | flo ts write --batch
```

- `--timestamp` is milliseconds since the epoch and must be > 0. Without it, a `--value` write is stamped by the server; `--fields` and a `--batch` line without a timestamp are stamped once by the CLI's clock, so all their fields share one timestamp.
- Values must be finite numbers; whole numbers past 2^53 are refused, because a float can't store them exactly.
- `--fields` sends one write per field and is not atomic. If one is refused, the error says how many were written.
- `--batch` reads line protocol from `--file` or stdin, with `--precision ns|us|ms|s` (default `ms`). Each line names its own measurement, tags and time, so `--batch` refuses a measurement, `--tags`, `--value`, `--fields` and `--timestamp`. A bad line is reported by line number, naming the token at fault, and none of its fields are written. The other lines are still written, and the command exits non-zero if any line failed. Backslash escapes, repeated tag keys or fields, and anything after the timestamp are refused.

### `flo ts floql`

Run a FloQL query.

```bash
flo ts floql "<query>"
```

Examples:

```bash
flo ts floql 'cpu_usage{host=web-01}[1h] | window(5m) | avg()'
flo ts floql 'temperature[24h] | window(1h) | max() | topk(3)'
```

## Cluster

### `flo cluster status`

Show this node's id, role (`leader`, `follower`, `replica`, `electing`,
`joining`, `diverged`, `guarded: catching up`, `guarded: confirming the term`,
`removed`), the leader it knows (`none` while electing
or joining), the term and the member count. `-o json` gives the same as one
object.

```bash
flo cluster status
flo cluster status -o json
```

### `flo cluster members`

Every member with its role (`voter`, `replica`, or `joining` for one added
that has not caught up yet), address, last
contact and lag, and the ids removed. Contact and lag are the leader's to
report; elsewhere they show `-`. `-o json` gives the same as one object.

### `flo cluster promote <id>...`

Make a caught-up replica a voter, one at a time, each answered once it
commits. Refused for a member that has not caught up.

### `flo cluster remove <id> [--yes]`

Remove a member, answered once the change commits; the id cannot rejoin.
Refused when it would leave no voter; `--yes` is required when it would leave
an even number of voters, or two. The leader may remove itself.
