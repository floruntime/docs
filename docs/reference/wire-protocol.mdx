---
title: Wire Protocol
lede: Binary wire protocol reference for the Flo client-server communication.
---

Clients talk to Flo over TCP on the client port (default **9000**) with a binary protocol: a fixed 32-byte header, then a payload. All integers are little-endian. The dashboard and metrics have their own HTTP ports.

## Request

### Header (32 bytes)

| Offset | Field | Type | Description |
|--------|-------|------|-------------|
| 0 | `magic` | `u32` | `0x004F4C46` (the bytes `F` `L` `O` `\0`) |
| 4 | `payload_length` | `u32` | Bytes of payload after the header |
| 8 | `request_id` | `u64` | Chosen by the client; the response carries it back |
| 16 | `crc32` | `u32` | CRC-32 of the header (this field excluded) and the payload |
| 20 | `op_code` | `u16` | The operation (see [OpCodes](#opcodes)) |
| 22 | `version` | `u8` | `0x01` |
| 23 | `flags` | `u8` | `0` |
| 24 | `reserved` | `[8]u8` | Zeros |

### Payload

```
[namespace_len:u16][namespace][key_len:u16][key][value_len:u32][value][options_len:u16][options]
```

An empty namespace is the `default` namespace for most operations. Options are a sequence of `[tag:u8][len:u8][value]` entries (see [Options](#options)).

### List operations

`kv_scan`, `stream_list`, `queue_list`, `ts_list`, `namespace_list`, `action_list`, `worker_list`, `processing_list` and `workflow_list_definitions` page across every shard. Their request value is:

```
[limit:u32][cursor]
```

`limit` 0, or anything over 1024, is a page of 1024. `cursor` is empty on the first page and otherwise the cursor the previous page returned, unchanged. Every list answer ends with:

```
[has_more:u8][cursor_len:u16][cursor]
```

Paging is not a snapshot. A cursor resumes each shard by name or by position, so names created or deleted between pages can be listed twice or skipped.

## Response

### Header (32 bytes)

| Offset | Field | Type | Description |
|--------|-------|------|-------------|
| 0 | `magic` | `u32` | `0x004F4C46` |
| 4 | `data_len` | `u32` | Bytes of data after the header |
| 8 | `request_id` | `u64` | The request's id |
| 16 | `crc32` | `u32` | CRC-32 of the header (this field excluded) and the data |
| 20 | `version` | `u8` | `0x01` |
| 21 | `status` | `u8` | See [Status codes](#status-codes) |
| 22 | `flags` | `u8` | `0` |
| 23 | `_pad` | `u8` | `0` |
| 24 | `reserved` | `[8]u8` | Zeros |

A response carries no opcode: the client knows which request it sent. On a refusal the data is a human-readable message.

## OpCodes

The protocol defines 100 operation codes, grouped by subsystem.

### System (0x000 – 0x00F)

| OpCode | Value |
|--------|-------|
| `ping` | `0x000` |

| `namespace_info` | `0x013` |
| `namespace_config_set` | `0x014` |
| `namespace_config_get` | `0x015` |

### Cluster (0x030 – 0x04F)

| OpCode | Value |
|--------|-------|
| `cluster_status` | `0x030` |
| `cluster_members` | `0x031` |
| `cluster_promote` | `0x032` |
| `cluster_remove` | `0x033` |

A `cluster_promote` value is the node id, u32 little-endian (4 bytes). A `cluster_remove` value is the node id, u32 little-endian, then one byte that is non-zero to allow a removal that leaves an even number of voters (5 bytes). Any other length is refused with `bad_request`. Both are answered with an empty value once the change commits; promoting a node that is already a voter is answered at once.

## Options

Tags the server reads. An option it doesn't recognise is ignored for now; that changes with the typed op table.

| Tag | Name | Value |
|-----|------|-------|
| `0x01` | `ttl_ms` | u64: Time-to-live in milliseconds (0 = no expiration) |
| `0x02` | `cas_version` | u64: Expected version for compare-and-swap |
| `0x03` | `if_not_exists` | void: Only set if key doesn't exist (NX) |
| `0x04` | `if_exists` | void: Only set if key exists (XX) |
| `0x05` | `limit` | u32: Maximum results for `kv_history` (newest first) and `ts_read` (earliest first); absent or 0 is all. List operations take theirs in the value |
| `0x08` | `routing_key` | string: Explicit routing key for shard co-location (overrides key-based routing) |
| `0x09` | `txn_id` | u64: Per-shard transaction ID (returned by kv_begin_txn) |
| `0x10` | `priority` | u8: Message priority (0-255; lower is taken first) |
| `0x15` | `count` | u32: Number of messages to dequeue |
| `0x17` | `block_ms` | u32: Block timeout - wait until exists (at most 5 min; 0 = don't wait) |
| `0x18` | `wait_ms` | u32: Watch timeout - wait for NEXT version change (at most 5 min; 0 = don't wait) |
| `0x21` | `stream_start` | [16]u8: Read records after this StreamID (exclusive) |
| `0x22` | `stream_end` | [16]u8: End StreamID for reads (inclusive) |
| `0x23` | `stream_tail` | void: Flag indicating tail read (start from end of stream) |
| `0x24` | `partition` | u32: Explicit partition index |
| `0x25` | `partition_key` | string: Key for partition routing |
| `0x26` | `max_age_seconds` | u64: Trim records older than this many seconds |
| `0x27` | `max_bytes` | Refused: byte-based trim isn't supported ([#183](https://github.com/floruntime/flo/issues/183)) |
| `0x28` | `dry_run` | void: Trim answers what it would remove and removes nothing |
| `0x29` | `retention_count` | u64: Retention policy - max event count |
| `0x2A` | `retention_age` | u64: Retention policy - max age in seconds |
| `0x2B` | `retention_bytes` | Refused: byte retention isn't supported ([#183](https://github.com/floruntime/flo/issues/183)) |
| `0x2C` | `force` | void: Force a destructive op (e.g. delete a non-empty stream) |
| `0x30` | `ack_timeout_ms` | u32: Time before unacked message auto-redelivers (overrides default) |
| `0x31` | `max_deliver` | u8: Max delivery attempts before DLQ (default: 10, 0=unlimited) |
| `0x60` | `ts_from_ms` | i64: Start of time range (inclusive, unix ms) |
| `0x61` | `ts_to_ms` | i64: End of time range (inclusive, 0 = now) |
| `0x62` | `ts_window_ms` | i64: Aggregation window size (ms) |
| `0x63` | `ts_aggregation` | string: Aggregation function name (avg, sum, count, min, max) |
| `0x64` | `ts_field` | string: Field name filter (empty = "value") |
| `0x65` | `ts_tags` | string: Comma-separated tag filters "key=val,key2=val2" |
| `0x67` | `ts_timestamp` | i64: A write's timestamp in ms; absent, 0 or less = the server's clock |
| `0x68` | `ts_raw_ttl` | string: Raw data TTL (e.g., "7d") |
| `0x69` | `ts_downsample` | string: refused — downsampling isn't supported ([#158](https://github.com/floruntime/flo/issues/158)) |
