title: Wire Protocol
lede: Binary wire protocol reference for the Flo client-server communication.

Flo uses a custom binary protocol for client-server communication on port **9000**. The protocol supports TLV (Type-Length-Value) encoding for efficiency and zero-copy parsing.

## Connection

Clients connect via TCP to the server's client port (default 9000). The first bytes sent identify the protocol:

| Magic Bytes | Protocol |
|-------------|----------|
| `FLO\x01` | Binary wire protocol |
| `GET`, `POST`, ... | HTTP (redirected to dashboard) |
| WebSocket upgrade | WebSocket (binary protocol over WS frames) |

The Acceptor thread peeks at the first bytes to detect the protocol and routes accordingly.

## Request Format

Every request has a fixed 32-byte header followed by a variable-length payload:

```
┌──────────────────────────────────────────────────────────────────┐
│                    Request Header (32 bytes)                      │
├──────────┬──────────┬───────┬──────────┬──────────┬──────────────┤
│ magic    │ opcode   │ flags │ req_id   │ payload  │ namespace    │
│ (4B)     │ (2B)     │ (2B)  │ (8B)     │ _len(4B) │ _hash (8B)  │
├──────────┴──────────┴───────┴──────────┴──────────┴──────────────┤
│ key_length │ padding                                              │
│ (2B)       │ (2B)                                                │
├────────────┴─────────────────────────────────────────────────────┤
│                    Payload (variable)                             │
│ [key bytes] [value bytes] [optional TLV fields]                  │
└──────────────────────────────────────────────────────────────────┘
```

### Header Fields

| Field | Type | Description |
|-------|------|-------------|
| `magic` | `u32` | Protocol magic: `0x464C4F01` ("FLO\x01") |
| `opcode` | `u16` | Operation code (see OpCode table) |
| `flags` | `u16` | Request flags (compression, etc.) |
| `req_id` | `u64` | Client-assigned request ID for response matching |
| `payload_len` | `u32` | Length of payload following the header |
| `namespace_hash` | `u64` | FNV-1a hash of the namespace string |
| `key_length` | `u16` | Length of the key in the payload |

## Response Format

```
┌──────────────────────────────────────────────────────────────────┐
│                   Response Header (24 bytes)                      │
├──────────┬──────────┬───────┬──────────┬──────────────────────────┤
│ magic    │ status   │ flags │ req_id   │ payload_len              │
│ (4B)     │ (2B)     │ (2B)  │ (8B)     │ (4B)                    │
├──────────┴──────────┴───────┴──────────┴──────────────────────────┤
│                    Payload (variable)                             │
└──────────────────────────────────────────────────────────────────┘
```

### Status Codes

| Code | Name | Description |
|------|------|-------------|
| `0x00` | `OK` | Operation succeeded |
| `0x01` | `NOT_FOUND` | Key / queue / stream not found |
| `0x02` | `BAD_REQUEST` | Invalid request parameters |
| `0x03` | `CONFLICT` | CAS version mismatch |
| `0x04` | `UNAUTHORIZED` | Authentication required |
| `0x05` | `OVERLOADED` | Server at capacity (retry) |
| `0x06` | `INTERNAL_ERROR` | Server error |
| `0x07` | `NOT_LEADER` | Node is not the leader for this partition |

## OpCodes

The protocol defines 167 operation codes organized by subsystem:

### KV Operations (0x100–0x118)

| OpCode | Value | Description |
|--------|-------|-------------|
| `kv_put` | `0x100` | Set key-value pair (returns new version) |
| `kv_get` | `0x101` | Get value + version by key |
| `kv_mget` | `0x102` | Multi-key get |
| `kv_delete` | `0x103` | Delete a key |
| `kv_scan` | `0x104` | Prefix scan |
| `kv_history` | `0x105` | Get version history |
| `kv_incr` | `0x10B` | Atomic counter (signed i64 delta, default +1) |
| `kv_json_get` | `0x10C` | Extract JSON sub-field via JSONPath |
| `kv_json_set` | `0x10D` | Atomically set a JSON sub-field |
| `kv_json_del` | `0x10E` | Atomically delete a JSON sub-field |
| `kv_touch` | `0x113` | Update TTL on existing key (no value rewrite). Value: 8-byte TTL in milliseconds; 0 clears it |
| `kv_persist` | `0x114` | Clear TTL (make key permanent) |
| `kv_exists` | `0x115` | Existence check (no value transferred) |
| `kv_begin_txn` | `0x110` | Open a per-shard transaction (returns `txn_id` + pinned partition hash) |
| `kv_commit_txn` | `0x111` | Commit a transaction atomically (returns `commit_index` + `op_count`) |
| `kv_rollback_txn` | `0x112` | Discard a transaction (idempotent) |
| `kv_txn_response` | `0x119` | Reply envelope for ops executed inside a transaction |

Response opcodes occupy `0x106–0x10A` and `0x116–0x118`. CAS is expressed as a TLV option on `kv_put`, not a separate opcode. Per-shard transactions (see [Transactions](/primitives/kv#transactions)) are scoped to a single partition and carry the open `txn_id` via the `txn_id` TLV option (tag `0x09`, u64 LE) on subsequent KV ops.

### Queue Operations (0x20–0x2F)

| OpCode | Value | Description |
|--------|-------|-------------|
| `queue_enqueue` | `0x20` | Add message to queue |
| `queue_dequeue` | `0x21` | Fetch and lease messages |
| `queue_ack` | `0x22` | Acknowledge messages |
| `queue_nack` | `0x23` | Negative acknowledge |
| `queue_peek` | `0x24` | Peek without leasing |
| `queue_touch` | `0x25` | Extend lease |
| `queue_dlq_list` | `0x26` | List DLQ messages |
| `queue_dlq_requeue` | `0x27` | Requeue from DLQ |

### Stream Operations (0x30–0x3F)

| OpCode | Value | Description |
|--------|-------|-------------|
| `stream_append` | `0x30` | Append record |
| `stream_read` | `0x31` | Read records |
| `stream_create` | `0x32` | Create stream |
| `stream_info` | `0x33` | Stream metadata |
| `stream_trim` | `0x34` | Trim old records |
| `stream_group_create` | `0x35` | Create consumer group |
| `stream_group_read` | `0x36` | Consumer group read |
| `stream_group_ack` | `0x37` | Consumer group ack |

### Time-Series Operations (0x1A0–0x1A6)

| OpCode | Value | Description |
|--------|-------|-------------|
| `ts_write` | `0x1A0` | Write one value: key = measurement, value = one finite f64, 8 bytes little-endian. Options: `ts_field` (default `value`), `ts_tags`, `ts_timestamp` (ms) |
| `ts_read` | `0x1A1` | Read raw points |
| `ts_query` | `0x1A2` | Windowed aggregation |
| `ts_floql` | `0x1A3` | Execute FloQL query |
| `ts_list` | `0x1A4` | List measurements or series |
| `ts_delete` | `0x1A5` | Delete series |
| `ts_retention` | `0x1A6` | Set retention |

Time-series option tags:

| Tag | Value | Type | Meaning |
|-----|-------|------|---------|
| `ts_from_ms` | `0x60` | i64 | Start of the time range (inclusive, unix ms) |
| `ts_to_ms` | `0x61` | i64 | End of the time range (inclusive; 0 = now) |
| `ts_window_ms` | `0x62` | i64 | Aggregation window (ms) |
| `ts_aggregation` | `0x63` | string | `avg`, `sum`, `count`, `min` or `max` |
| `ts_field` | `0x64` | string | Field name (default `value`) |
| `ts_tags` | `0x65` | string | `key=val,key2=val2` |
| `ts_timestamp` | `0x67` | i64 | A write's timestamp in ms; absent = the server's clock |
| `ts_raw_ttl` | `0x68` | string | Raw data TTL, e.g. `7d` |
| `ts_downsample` | `0x69` | string | Refused: downsampling isn't supported |

A `ts_write` value that isn't exactly 8 bytes, or is NaN or infinite, is refused with `bad_request`.

## TLV Extended Fields

Operation-specific parameters travel as TLV (Type-Length-Value) options at the end of the request payload:

```
┌──────┬────────┬───────────┐
│ tag  │ length │ value     │
│ (1B) │ (1B)   │ (var)     │
└──────┴────────┴───────────┘
```

A value is at most 255 bytes. Integers are little-endian; a flag option has length 0 and is set by being present.

### KV options (0x01–0x0F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x01` | `ttl_ms` | u64 | Time-to-live in ms; 0 = no expiry. Any length other than 8 bytes is refused |
| `0x02` | `cas_version` | u64 | Expected version for compare-and-swap |
| `0x03` | `if_not_exists` | flag | Write only if the key doesn't exist |
| `0x04` | `if_exists` | flag | Write only if the key exists |
| `0x05` | `limit` | u32 | Maximum results for scan and list operations |
| `0x06` | `keys_only` | u8 | 1 = return keys without values in a scan |
| `0x07` | `cursor` | bytes | Pagination cursor from a previous scan |
| `0x08` | `routing_key` | string | Routing key that overrides key-based shard routing |
| `0x09` | `txn_id` | u64 | Per-shard transaction id returned by `kv_begin_txn` |

### Queue options (0x10–0x1F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x10` | `priority` | u8 | Message priority, 0–255; higher is more urgent |
| `0x11` | `delay_ms` | u64 | Delay before the message becomes visible |
| `0x12` | `visibility_timeout_ms` | u32 | How long a dequeued message stays invisible |
| `0x13` | `dedup_key` | string | Deduplication key |
| `0x14` | `max_retries` | u8 | Retry attempts before the message goes to the DLQ |
| `0x15` | `count` | u32 | Number of messages to dequeue |
| `0x16` | `send_to_dlq` | u8 | 1 = send failed messages to the DLQ |
| `0x17` | `block_ms` | u32 | Wait until a result exists; 0 = don't wait, at most 300000 |
| `0x18` | `wait_ms` | u32 | Wait for the next version change; 0 = don't wait, at most 300000 |

### Stream options (0x20–0x2F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x21` | `stream_start` | StreamID | Read records after this id (exclusive) |
| `0x22` | `stream_end` | StreamID | End id for reads (inclusive) |
| `0x23` | `stream_tail` | flag | Start from the end of the stream |
| `0x24` | `partition` | u32 | Explicit partition index |
| `0x25` | `partition_key` | string | Key for partition routing |
| `0x26` | `max_age_seconds` | u64 | Maximum age for retention |
| `0x27` | `max_bytes` | u64 | Maximum size for retention |
| `0x28` | `dry_run` | flag | Preview what would be deleted without deleting |
| `0x29` | `retention_count` | u64 | Retention policy: maximum event count |
| `0x2A` | `retention_age` | u64 | Retention policy: maximum age in seconds |
| `0x2B` | `retention_bytes` | u64 | Retention policy: maximum bytes |
| `0x2C` | `force` | flag | Force a destructive operation, such as deleting a non-empty stream |

`0x20` is reserved. A StreamID is 16 bytes: `timestamp_ms` then `sequence`, each a big-endian u64.

### Consumer group options (0x30–0x3F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x30` | `ack_timeout_ms` | u32 | Time before an unacked message is redelivered |
| `0x31` | `max_deliver` | u8 | Delivery attempts before the DLQ; 0 = unlimited |
| `0x32` | `subscription_mode` | u8 | 0 = shared, 1 = exclusive, 2 = key_shared |
| `0x33` | `redelivery_delay_ms` | u32 | Delay before a nacked message is visible again |
| `0x34` | `consumer_timeout_ms` | u32 | Remove a consumer from the group after this long idle |
| `0x35` | `no_ack` | flag | Ack on delivery (at-most-once) |
| `0x36` | `idle_timeout_ms` | u64 | Minimum idle time before a stuck message can be claimed |
| `0x37` | `max_ack_pending` | u32 | Maximum unacked messages per consumer |
| `0x38` | `extend_ack_ms` | u32 | How far a touch extends the ack deadline |
| `0x39` | `max_standbys` | u16 | Maximum standby consumers in exclusive mode |
| `0x3A` | `num_slots` | u16 | Hash slots for key_shared mode |

### Worker and action options (0x40–0x4F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x40` | `worker_id` | string | Worker identifier |
| `0x41` | `extend_ms` | u32 | Lease extension in ms |
| `0x42` | `max_tasks` | u32 | Maximum tasks to return in one batch |
| `0x43` | `retry` | u8 | 1 = retry on failure |

### Workflow options (0x50–0x5F)

| Tag | Name | Type | Meaning |
|-----|------|------|---------|
| `0x50` | `timeout_ms` | u64 | Workflow or activity timeout |
| `0x51` | `retry_policy` | bytes | Serialized retry policy |
| `0x52` | `correlation_id` | string | Correlation id for tracing |
| `0x53` | `subscription_id` | u64 | Subscription id for stream subscriptions |
